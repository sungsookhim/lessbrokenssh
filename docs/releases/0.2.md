lessbrokenssh 0.2 adds Ed25519 keys and a faster key exchange, makes key login work with key files saved on the Mac, draws box drawing and Braille faster, and fixes a hang when the server drops the connection. It's a fork of [ssheven](https://github.com/cy384/ssheven) 0.9.0, an SSH client for Mac OS 7, 8 and 9.

## Downloads

| File | For |
|---|---|
| `lessbrokenssh-0.2-68020.bin` | any 68k Mac with a 68020 or 68030 (Mac II family, LC, LC II, LC III, IIci, SE/30) |
| `lessbrokenssh-0.2-68040.bin` | 68040 Macs (Quadra, Centris, LC 475, LC 575) |
| `lessbrokenssh-0.2-g3.bin` | any PowerPC Mac (601, 603, 604, G3, G4); tuned for the G3 |
| `lessbrokenssh-0.2.dsk` | an HFS disk image with all three apps and a Read Me, for emulators and disk-image tools |

The `.bin` files are MacBinary: decode them on the Mac with StuffIt Expander, or transfer them with a tool that understands MacBinary. Only one app is needed.

Tested on an iMac G3 (Mac OS 9, `g3`) and an LC 475 (`68040`). The `68020` build hasn't been tried on a 68020 or 68030 Mac yet.

## What's new since 0.1

- **Ed25519 keys**, the `ssh-keygen` default, with or without a passphrase. RSA and ECDSA keys still work.
- **curve25519-sha256 key exchange**, used when the server offers it (OpenSSH has for years). It's faster than the ECDH and Diffie-Hellman exchanges, which matters on 68k.
- **Key files saved on the Mac work.** A key pasted into SimpleText, or copied over as text, has Mac line endings, and the login failed with "Username/public key combination invalid" as if the server had refused the key. ssheven has the same problem. Key files are also opened read-only now, so a locked key works.
- **Faster drawing** of box drawing, blocks and Braille: each row's glyphs go to the screen with one copy per color run instead of one per character. btop's graphs and window redraws are noticeably lighter on the LC 475.
- **No more hang when the server drops the connection** (a server reboot, a killed session): the app reports the error and disconnects. ssheven can freeze here.

**Settings from 0.1 are kept.** A server without an ECDSA host key now presents its Ed25519 key instead of the RSA one, so the first connection to it after the upgrade asks to accept the key, like a new host; both stay in `lessbrokenssh known_hosts`. Servers with an ECDSA key (most, including stock Ubuntu) keep using it.

## Requirements

- System 7.1 or later (below 7.5, the Thread Manager extension)
- Open Transport
- 4 MB of free memory (3 MB minimum)
- No FPU needed

## Known gaps

- **CJK needs the system's language kits.** Without them (like an English System 7.6), Korean and Japanese show `◊`. Hangul syllables outside the 2,350 in KS X 1001 also show `◊`.
- **Truecolor** needs `AcceptEnv COLORTERM` in the server's sshd, or `export COLORTERM=truecolor` in your shell profile there.
- **btop is still demanding on the LC 475**, mostly from decrypting and parsing its output. Setting `update_ms` to 4000 or more, `truecolor = False` and a flat theme like `TTY` helps.
- **Text you copy or type leaves the Mac as Mac Roman,** not UTF-8.
- **A wrong key passphrase clears the saved key paths**, so the key files have to be picked again on the next connect.
